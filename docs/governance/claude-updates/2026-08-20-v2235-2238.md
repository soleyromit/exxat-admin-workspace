### ADOPT-2: Create `.claude/hooks/notification-capture.py` and add `Notification` hook to root `.claude/settings.json`

**Upstream evidence**: CC CHANGELOG 2.1.224 — "Added background agent notifications in `claude agents` — sessions that need input or finish now fire the `Notification` hook (`agent_needs_input` / `agent_completed`)." Originally proposed in v2186-2201 ADOPT-2, re-elevated in v2222-2226 ADOPT-2 Step 1, documented as applied — but the file was never created on disk.

**New evidence from this batch**: TS SDK 0.3.233 — "Notification hooks now fire for pending permission prompts on the SDK path, matching the interactive REPL behavior." This means the capture script will receive permission-prompt events in addition to agent-lifecycle events and must filter to avoid noise.

**Status upstream**: GA (CC 2.1.224 stable; TS SDK 0.3.233 stable).

**What it gives us**: background subagent completions currently produce zero hook-side logging. `subagent-stop.py` only fires for in-session subagents. Until notification-capture.py runs and logs at least one live `agent_completed` payload, Step 2 parse cannot be safely written. No payload has ever been captured because the file was never created despite being documented as wired.

**How to wire — two parts:**

Part A — create `.claude/hooks/notification-capture.py`:

```python
#!/usr/bin/env python3
"""Notification hook capture (Step 1 of two-step plan).
Captures agent_completed payloads to notification-payloads.log for Step 2 parse-spec.
Passes through silently for all other events (permission prompts, agent_needs_input, etc).
TS SDK 0.3.233: Notification now also fires for permission prompts — filter is required.
NOTE: field path for notification type is unconfirmed from changelog; inspect first capture.
"""
import json, sys, pathlib, datetime

raw = sys.stdin.read()
try:
    payload = json.loads(raw)
except json.JSONDecodeError:
    sys.exit(0)

# Candidate field paths for notification type (verify against first captured payload)
notification_type = (
    payload.get("notification", {}).get("type")
    or payload.get("type", "")
)
if notification_type not in ("agent_completed",):
    sys.exit(0)

log_path = (
    pathlib.Path(__file__).parent.parent.parent
    / "docs" / "governance" / "notification-payloads.log"
)
log_path.parent.mkdir(parents=True, exist_ok=True)
with log_path.open("a") as f:
    f.write(f"# {datetime.datetime.utcnow().isoformat()}Z\n")
    f.write(raw.strip())
    f.write("\n\n")

sys.exit(0)
```

Part B — add `Notification` block to root `.claude/settings.json` hooks object (after `SubagentStop` at line 235, before `Stop`):

```json
"Notification": [
  {
    "hooks": [
      {
        "type": "command",
        "command": "python3 \"$CLAUDE_PROJECT_DIR\"/.claude/hooks/notification-capture.py",
        "timeout": 5
      }
    ]
  }
]
```

**Post-application verification**: after applying, spawn a background subagent from root workspace context, then check `docs/governance/notification-payloads.log` for a new entry. If the log is empty after a confirmed background-agent completion, temporarily remove the type filter (capture all Notification events) to observe the raw payload shape, then restore the filter.

**Replaces / consolidates with**: does not replace `SubagentStop`. Both hooks remain: `SubagentStop` (in-session subagents) and `Notification/agent_completed` (background-session subagents).

**Risk**: read-only; exits 0 on any parse failure. TS SDK 0.3.233 filter prevents permission-prompt events from polluting the log. Rollback = remove Notification block from settings.json and delete notification-capture.py.
