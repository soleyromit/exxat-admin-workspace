Date: 2026-10-09 · Tool: Mobbin MCP (`claude_ai_Mobbin`, web, deep mode; 7 screen searches plus 1 flow search; every returned image was viewed, not only its metadata). The `mobbin` server (`mcp__mobbin__*`) was not used (it was not authenticated in the previous session and I did not retry).
Companions: `docs/design/mobbin-evidence.md` (job type 8, two-pane configuration workspace: Klaviyo, Greptile, Chatbase) and `docs/research/meetings/2026-10-08-mobbin-s09-configure-patterns.md` (config with preview, rule builders, save-blocking validation) are **not repeated here**. Consumed by `docs/design/kits-variants-2026-10-09.md`.
Patterns only, no pixel copying. **None of these products is clinical education, credentialing, or an accreditation tool.** Fit ratings are mine `[INFER]`. **Strong** = answers a named requirement of the Kits job, **Partial** = one idea transfers, **Weak** = does not answer the job (kept so the next person does not re-find it).
The target user is a program administrator with 40 to 200 imported, unconfigured skills `[REQ §3]` `[CALL 09-23 line 112]`, under three rules that most references break: no default evaluation model `[REQ SC-02]`, every automated output is a draft needing explicit confirmation `[REQ IM-13]`, and an unsatisfiable configuration cannot be saved `[REQ SC-18]`.

**Honest read of Part 1.** Every reference applies **one field** to a selection. None applies a structured, dependent configuration (model, then rule, then criteria, then per-setting minimums) to a group, and none is gated by "this combination can never be satisfied". The apply step (summary, target list, one confirm, keep-by-default for already-set values, a spot-check) can be assembled from #1, #3, #5 and #10. The configuration editor itself has **no analogue** and reuses S-09 (`docs/build/contracts/S-09-skill-configure.md`).

## Where no reference exists (stated plainly)

1. **"Select similar" from selected rows.** The searches returned no screen where a person selects a few rows and a control proposes the similar ones. The closest is Superhuman's example list with include and exclude (#14), where the rule is a typed prompt. The interaction in variant C is ours and untested.
2. **AI grouping of many short, homogeneous items into named groups with member counts, for the purpose of configuring the group.** Peec (#11), Canny (#12) and Maze (#13) give the inbox, the verbs and the merge-and-name step, but none groups items to configure them together.
3. **A configuration template applied as independent copies, with a visible "this skill has since been changed" state (drift).** No reference. `docs/ux/08` P-05 already defines "independent copies" `[INFER]`; the drift cue is new in this pack `[INFER]`.
4. **Applying a dependent, validated configuration to a group.** All references apply one field (Part 1 honest read). Per-target validation of an unsatisfiable rule `[REQ SC-18]` has no analogue.
5. **A "no default model" group editor.** Every configuration tool here either pre-fills (ClickUp #15, Square #16) or defaults to "keep". Four unselected tiles are the S-09 pattern and nothing from Mobbin improves on it.
6. **The Jev constraint set** (typed answers only, abstain surfaced as "no suggestion", evidence from code). None of the AI references show evidence or an abstain path; all of them hide the model behind a button, and two (#12, #22) expose an auto-accept mode or a score.

## What this research changes in the design

| Finding | Effect |
|---|---|
| Suggestions sit in a band above the real list with two verbs (#11, #12, #24) | Variant A "Suggested kits" inbox; "Dismiss" is remembered |
| Per-item include and exclude beside the rule (#14) | Variant C "Select similar" shows candidates with a checkbox and the shared words; nothing is selected until ticked |
| Jira moved from a 4-step wizard to in-list bulk edit (#1) | Treat the wizard (variant B) as the riskiest container; it is the one the market is leaving |
| Apply = summary, target list, one confirm, per-target checkbox (#1, #5, #10) | Shared "Apply" dialog for all three variants |
| "Keep current value" default (#3) | When a kit is applied over configured skills, each section defaults to keep |
| No-match as a stated result (#20) | "No suggestion" is a visible state, not an empty gap |
| Auto-accept (#12), scores and sliders (#22), AI-written values (#15, #23) | Named anti-patterns in the spec; none appear in any variant |

## Not verified

Findings are single-frame previews; no interaction, timing or keyboard behaviour was observed. Fit ratings are my judgment. No product was used live. Jira's "older experience" banner (#1) is read from one frame and may be a staged rollout, not a direction `[INFER]`.
